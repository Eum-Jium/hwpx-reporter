# 공공기관 표준서식 규격 (정본 실측)

종전에는 이 내용을 `basic.hwpx` 라는 **렌더되지 않는 양식**으로 갖고 있었다.
양식 목록에 떠 있으면서 고르면 본문을 못 채우니, 무엇을 고르라는 것인지가 매번
헷갈렸다. 서식 규격은 문서로 읽을 것이지 찍을 것이 아니라서 md 로 옮겼다.

값은 전부 정본 hwpx 실측이고, 코드의 단일 기준 모듈과 같은 수를 적는다
(`hwpx_core/tablespec.py` · `gaps.py` · `hwpx_skeleton/style.py`).
**여기 값을 고쳐도 렌더 결과는 안 바뀐다** — 렌더는 양식 문단을 복제해 만든다.

## 판면

| 항목 | 값 |
|------|-----|
| 용지 | A4 (595 × 841.9pt) |
| 여백 | 위·아래 15mm(42.5pt), 좌·우 20mm(56.7pt) |
| 머리말·꼬리말 | 각 28.35pt |
| 본문 영역 | 세로 **700.1pt** (위 70.9pt ~ 아래 771.0pt) = 24pt 줄로 **29줄** |
| 줄간격 | 160% (취지 박스만 150%) |
| 정렬 | 양쪽정렬(JUSTIFY) |

## 글자

| 단위 | 앞칸 | 크기 | 글꼴 |
|------|------|------|------|
| 제목(제목상자) | — | 23pt | HY헤드라인M |
| `1.` 헤딩 | 0칸 | 16pt | HY헤드라인M (자동번호) |
| `☐` 항목 | 1칸 | 15pt | 휴먼명조 |
| `◦` 세부 | 2칸 | 15pt | 휴먼명조 |
| `*` 참고 | 4칸 | 13pt | 한양중고딕 |
| 표 셀 | — | 13pt | 한양중고딕, 가운데 (헤더행만 볼드) |

`-`(3칸)·`·`(4칸)도 엔진은 렌더하지만 **새로 쓰지 않는다** — 계층은 `☐ → ◦` 두 단계다.

## 간격 (빈 문단의 글자 크기로 준다)

| 자리 | 크기 |
|------|------|
| 새 섹션(헤딩) 앞 | 8pt |
| 헤딩 → 첫 ☐ / ☐ 사이 | 5pt |
| ☐ → 하위 ◦ / 참고 | 3pt |
| 제목·일시 아래 | 1pt |

## 표

| 항목 | 값(HWPUNIT) | 환산 |
|------|------------|------|
| 전체 폭 | 46,063 | 본문 폭 |
| 첫 열 폭 | 10,231 | 13pt 기준 7자 |
| 행 높이 | 1,900 | 19pt |
| 이미지칸 높이 | 17,865 | — |
| 캡션칸 높이 | 2,385 | — |

셀 글자 수는 **첫 열 7자 · 나머지 열 13자**를 넘으면 두 줄로 접혀 행 높이가 들쭉날쭉해진다.

## 쪽 단위 분량

한 쪽은 **29~32줄**이고 줄당 높이는 본문 24pt · 표 행 19pt · 각주 21pt다.
마지막 쪽 아래 여백은 5줄(130pt) 안팎까지 정상이다. 쪽수는 양식이 아니라
**본문 분량**이 정한다 — 자세한 것은 양식 스킬(hwpx-template) SKILL.md 의 「분량」을 볼 것.

## 쪽 채움 — 본문과 붙임에 같이 적용

한 쪽을 채웠다고 보는 최소 높이는 **571pt**(본문 영역 700.1 − 여백 상한 129)다.
`hwpx_core.volume` 이 이 수치의 단일 기준이고, 렌더가 붙임마다 미리 확인한다.

## 붙임·참고 페이지

본문 뒤에 붙는 별지는 정본에서 세 가지 형태로 쓴다. 엔진은 `attachments=[…]` 로
붙임을 만든다(`references/attachments.md`).

- `붙임1` / `붙임2` — 자료 별지. 표제 줄 뒤에 ☐·◦ 와 표가 온다.
- `참고` — 근거·배경 별지. 구성은 붙임과 같다.
- 본문 끝의 `붙임  1. 000` 목록은 둘째 줄부터 6칸 들여쓴다.

## 메모 (검토 의견)

메모는 별도 주석 파트가 아니라 **본문 안의 필드**다. 메모를 걸 글자 범위를
`hp:fieldBegin type="MEMO"` … `hp:fieldEnd` 로 감싸고, 메모 내용은 fieldBegin 안의
`hp:subList` 에 문단으로 들어간다. 단일 기준은 `hwpx_core/memo.py` 이고,
`scripts/review_memo.py` 로 쓴다.

조각이 셋이고 하나라도 빠지면 한/글이 메모를 안 보여 준다.

| 조각 | 자리 | 값 |
|------|------|-----|
| 메모 상자 모양 | header.xml `hh:refList` 끝 | `hh:memoPr` — 폭 15591, 테두리 `#B6D7AE`, 채움 `#F0FFE9`, 활성 `#CFF1C7`, `memoType="NOMAL"` |
| 모양 참조 | 섹션 `hp:secPr@memoShapeIDRef` | 위 `memoPr@id` |
| 메모 본체 | 본문 `hp:run` 안 | `fieldBegin`(파라미터 7개 + subList) … `fieldEnd@beginIDRef` |

- `Contents/memoExtended.xml`(`he:memosEx`, 답글 연결)은 **만들지 않는다**. 답글이
  없으면 빈 파트이고, **2021 확장**이라 `content.hpf` 에 등록된 그 항목을 만난
  구버전 한/글은 파일을 아예 안 연다(검토본 59개가 다른 PC 에서 안 열린 원인).
  원본에 이미 있으면 그대로 둔다.

- `memoType` 의 `NOMAL` 은 오타가 아니라 한/글이 실제로 쓰는 철자다.
- 파라미터의 `MemoShapeIDRef` = `65535` 는 '지정 없음', 곧 secPr 를 따르라는 뜻.
- **작성시각의 정본은 `CreateDateTime` 이 아니라 `Command` 의 숫자 두 자리**다 —
  `MEMO/<모양>/<번호>/<FILETIME 하위>/<FILETIME 상위>/<작성자>/\;;` 이고, 한/글은
  열 때 그 값으로 `CreateDateTime` 을 다시 계산해 덮어쓴다. 임의값을 넣으면
  메모 상자에 엉뚱한 날짜가 뜬다(처음에 넣었더니 2785년으로 고쳐 저장했다).
- `CreateDateTime` 문자열은 **로컬 시각(KST)에 Z 를 붙인** 한/글 관례를 따른다.
- 메모 문단은 `메모`(engName=Memo) 스타일 — 없는 양식이면 0번(바탕글)로 떨어진다.
- 기존 문서를 고쳐 쓸 때는 **루트의 xmlns 선언 묶음을 그대로 되살린다**. ET 는
  실제로 쓰인 접두사만 다시 써내는데, 한/글은 조각마다 늘 같은 묶음을 적어
  두고 구버전은 그것이 줄어든 파일을 안 연다(`serialize(el, like=원본바이트)`).
- 필드는 글자 흐름에서 한 칸씩 차지하므로 **그 문단의 `linesegarray` 는 지운다**
  (남기면 줄 좌표가 밀려 글자가 겹친다. 한/글이 열 때 다시 계산한다).
