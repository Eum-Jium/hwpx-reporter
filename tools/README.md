# tools — 보고서 작성·검증 도구

렌더 결과를 **실측으로** 확인하는 도구와, 그 도구로 규격을 맞춰 쓴 견본 본문이다.
패키지(`packages/`)가 문서를 만든다면, 여기는 **만든 문서가 실제 지면에서 규격대로
나오는지** 확인한다 — 자수만으로는 줄바꿈을 판정할 수 없기 때문이다.

```
tools/
  verify/    linebreak·advise·fit — 줄바꿈 예측/조정
             hwp_pages — 실제 쪽수·PDF, hwp_resave — 한/글 재저장 왕복 대조
  samples/   *_body.py — 견본 본문 + 규칙 자체검사(그대로 렌더까지)
```

실행은 리포 venv 로: `venv/Scripts/python.exe`
필요 패키지: 리포 5종 editable. **`pywin32`**(한/글 COM)는 `hwp_pages.py`·`hwp_resave.py`
에만 필요하다. PDF 좌표 대조(아래 검증 절차 3)는 PDF 도구(예: pymupdf)로 따로 한다.

## verify/

| 파일 | 하는 일 |
|---|---|
| `hwp_pages.py <hwpx>` | 한/글 COM 으로 열어 **실제 쪽수** 출력 + 같은 이름 PDF 저장. HWPX 는 쪽 정보를 파일에 담지 않아 쪽수 확인은 이 경로뿐이다. 보안 모듈 미등록이라 승인이 **약 1시간**만 유지된다 — 만료 후엔 접근 승인 대화상자가 뜨므로 창을 띄우게 해 두었다("허용" 클릭. 숨기면 무한 대기) |
| `hwp_resave.py <hwpx> [저장할.hwpx]` | 한/글로 **열어서 다시 저장**시킨 뒤 원본과 대조 — 본문 줄과 메모 값(작성자·시각·내용·걸린 본문)이 그대로 살아 돌아오는지 본다. 파일이 열리는 것은 XML 이 문법적으로 멀쩡하다는 뜻일 뿐이고, 한/글이 그 구조를 **인식했는지**는 재저장본에 남았는지로만 안다(인식 못 한 조각은 조용히 사라진다). 차이가 있으면 종료코드 1. 메모 `Command` 의 숫자를 난수로 넣었다가 한/글이 작성시각을 2785년으로 고쳐 저장한 것을 이 도구가 잡았다 |
| `linebreak.py <본문.txt>` | 줄바꿈 지점 예측 — 첫 줄이 낱말 중간에서 끊기는지 판정. 실측 advance 기반(오탐·미탐 0). `fill_ratio()` 로 마지막 줄 채움률도 준다 |
| `advise.py` | 끊긴 문장에 "앞부분 ±N pt(≈N자)" 조정량 계산 — linebreak 모델 공유 |
| `fit.py` | 슬롯 조합 탐색 — 규격(◦ 66~70자) + 어절 맞춤을 동시에 만족하는 문장 찾기 |

> ⚠️ **확인용 PDF 는 반드시 한/글 자신에게 시킨다**(`FileSaveAsPdf` 또는 `SaveAs(.., "PDF")`).
> `Microsoft Print to PDF` 프린터로 뽑으면 한컴 HFT 글꼴(휴먼명조·한양중고딕)의
> **한글 글리프가 통째로 빠진다.** 라틴·숫자·한자·기호는 남아서 "글꼴이 깨졌다"고
> 오진하기 딱 좋은데, 문서 자체는 멀쩡하고 프린터 드라이버가 HFT 를 임베드하지
> 못하는 것뿐이다(26-09-02 실측).

## samples/

견본 본문과 **규칙 자체검사**가 한 파일에 있다. `python tools/samples/plan_body.py`
로 검사만, `--render` 를 붙이면 렌더까지 한다(`--dump` 는 meet·train 에서 줄별 상태 출력).
`chart_body.py` 는 검사 없이 바로 렌더한다.

산출물은 리포 루트 **`output/<YYYY-MM-DD>/`** 에 떨어진다(`samples/outdir.py`).
파일 이름에 이미 시각이 붙어 한 줄이 길므로 날짜는 폴더로 올려 그날 것만 본다.
`output/` 전체는 .gitignore 대상 — 견본 본문에서 언제든 다시 렌더한다.

검사 항목(파일마다 5~9종 — adv·tres 가 전부): 분량 규격 · 용언 어미 종결 · 종결어 중복 · 을/를 잔존 ·
금지 계층(`-` `·`) · 표 첫 열 7자 · ASCII 물결(`~`) 잔존 · 낱말 중간 끊김 ·
둘째 줄 채움률 91% 미만.

| 파일 | 문서 |
|---|---|
| `plan_body.py` | 민원 대기시간 단축 추진계획 (plan, 2쪽) |
| `train_body.py` | 표준서식 문서 작성 교육 추진계획 (plan, 2쪽) |
| `meet_body.py` | 표준서식 개선 실무협의회 개최 계획 (plan, 1쪽) |
| `tres_body.py` | 표준서식 문서 작성 교육 결과보고 (result, 1쪽·표 2개) |
| `adv_body.py` | 표준서식 자동화 2단계 고도화 추진계획 (plan, 3쪽·그림 2개) |
| `chart_body.py` | AI 관련 기준 체계 (plan, 도해 1개 · 기관 내규 이름·날짜는 가상) — 제도 체계도를 46×61 모눈 표로 그리고 상자마다 기관 표장을 얹는다. 표장은 `assets/mark_*.png`(중립 도형 — 실제 기관 표장은 리포에 안 들인다) |
| `body.txt` | 문서 자동화 시스템 도입 결과 (result) 본문만 |

## 실측 상수 (휴먼명조 15pt, 정본 양식)

- ◦ 두 줄 용량 **645pt**(첫 줄 331 + 둘째 줄 314) ≈ 비공백 **51자**,
  □ 한 줄 용량 **337pt**, ◦ 첫 줄 **26자** / 연속 줄 **25자**(공백 제외)
- 글자 advance(`linebreak.py` 상수와 동일): 한글 **10.67** · 태그 볼드 한글 **11.15** ·
  공백(자연) **5.27** · 숫자 **5.27** · 괄호 **3.6** · % **8.95** · 가운뎃점 **4.08**,
  본문 오른끝 **R=381.9**
- 이미지자리 1개(자리표) = **202.5pt** — 그림칸 178.65 + 캡션칸 23.85. 종전 이 줄에
  적혀 있던 170pt 는 실측과 달랐다(08-19 PDF 가로선 y 355.5 → 534.0 로 재확인).
  **실물 그림을 넣으면 칸이 그림 높이를 따라간다** — 20mm 그림은 62.3pt 였다.
  값은 `hwpx_core.volume.image_slot_pt()` 한 곳에 있고 `test_volume.py` 가 붙든다
- ⚠️ 양쪽정렬은 공백을 ~6.0 까지 늘린다 — **줄나눔 판정엔 자연폭(5.27)** 을 쓴다.
  자수만으로는 판정할 수 없다(숫자·괄호가 섞이면 같은 자수라도 폭이 다르다).

## 검증 절차

1. 본문 작성 → `python tools/samples/<이름>.py` 로 자체검사(렌더 전에 전건 통과)
2. `--render` 로 렌더 → `verify/hwp_pages.py` 로 **실제 쪽수** 확인 + PDF 추출
3. PDF 좌표를 실측해 예측과 대조 — 줄바꿈 지점·채움률·쪽 배치
   ※ 폭 필터로 짧은 줄을 걸러내면 **1글자 꼬리를 놓친다** — 연속 줄은 들여쓰기
     x좌표로 판정한다
   ※ 2쪽 이상이면 PDF 가 **가로 A4 한 장에 두 쪽**으로 나올 수 있다(모아찍기).
     엔진은 `PrintMethod=0` 으로 정규화하지만, 밖에서 받은 문서는 확인이 필요하다
